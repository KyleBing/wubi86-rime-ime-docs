# 词库与同步

用户词、扩展词库和主码表是分开的。自造词进用户词，不改主码表。同步只动个人词库，规则跟 Rime 一样：改的是用户数据目录里的 yaml，不是程序包里的内置文件。

## 同步什么

云端只备份这一份文件：

```
wubi86_jidian_user.dict.yaml
```

它就是方案里 `import_tables` 中的个人私有词库。Mac、iOS、Windows、码表助手登录同一个 portal 账号后，同步的都是这一份内容（分组、词条、编码、权重、备注）。

主码表、扩展词库、其它自定义 dict，**不会**跟着账号双向同步。需要的话请自行拷进用户数据目录，或在方案里按 Rime 惯例加入 `import_tables`，再重新部署。

### 容量

| 限制 | 说明 |
| --- | --- |
| 内容上限 | **40 000 字**（各端与码表助手同一阈值） |
| 文件体量 | 常见个人词大约 **不超过 100 KB** |
| 条数参考 | 大约够放 **5 000 条** 个人词，日常完全够用 |

超限时上传会失败，需要先删掉不常用的词再同步。主码表、扩展词库体积再大也不占这个额度——它们本来就不进这份云端备份。

## 同步能做什么

各端实现同一套逻辑（对比差异、手动覆盖、自动三方合并）。登录后可用：

| 功能 | 做什么 |
| --- | --- |
| 对比差异 | 只拉取云端个人词做比较，不改本地。列出仅本地 / 仅云端 / 内容不同（同一条看分组 + 词 + 编码，权重和备注不一致算不同） |
| 增量合并 | 保留本地词条，把云端多出来的并进来，再把合并结果上传 |
| 本地 → 云端 | 用本地整份覆盖云端备份 |
| 本地 ← 云端 | 用云端整份覆盖本地个人词 |
| 自动同步 | 按修订号做三方合并：只推有变化的部分；本地删掉且云端未再改的词不会被加回来；两边都改过的同一条保留本地，不静默覆盖 |
| 获取扩展词库 | **单向拉取** `wubi86_jidian_extra.dict.yaml`：用线上镜像覆盖本地扩展文件，不做双向同步 |

箭头指向被覆盖的一侧。覆盖前建议先对比一次。

### 自动同步的节奏

打开后大约 **2 秒** 查一次；本地改词约 **3 秒** 后再同步；运行中大约每 **10 分钟** 查一次。云端修订号没变且本地也没改时，不会整份下载正文。

- macOS / Windows：输入法或设置里打开「自动同步」即可。
- iOS：需登录并允许键盘「完全访问」；退到后台后系统不保证仍按 10 分钟跑，下次打开键盘或 App 会补上。

正在打字时若本地词库被同步写回，会等这次输入结束再重新加载，避免打断编码。

## 用户词本身

词按分组存放。添加时填写词条和编码。有单字字典时，编码会按 [自造词](/guide/custom-words#编码怎么来) 同一套规则生成。分组可以新建、重命名、删除。删分组不会把词条散到别处。快捷造词写入当前选中的分组。

iOS 在主 App 里管理这些分组。Mac 的界面见文末。

## 扩展词库

扩展词库和用户词、主码表分开。从线上获取时，会用线上内容覆盖本地扩展文件，不能在这个操作里逐条编辑。获取前请确认本地扩展词库没有需要留下的改动。Mac 上这个按钮在「用户词」页，叫「获取扩展词库」。

若要长期自用一份大词库，更稳妥的做法是自己维护 dict 文件并加入 `import_tables`，而不是塞进个人同步文件。

## 在 macOS 的设置里

「设置 → 用户词」左边是分组，右边是词条。可以添加、改编码、拖动排序、重命名或删除分组。删分组不会把词条散到别处。快捷造词写入当前选中的分组。

「设置 → 账户」登录。登录后回到「用户词」页做对比、合并和覆盖，或打开「自动同步」。

「词库目录」管理 Rime 用户数据放在哪，以及重新部署、复位。

「单字字典」从当前选中的主码表抽出单字编码，供添加词条和快捷造词自动生成词组编码。换了主码表后，在这里重新生成一次字典。
